# Boxing Vision

Локальный инвесторский прототип разбора боксёрских видео. Приложение предлагает калибровку двух бойцов, сохраняет траектории и позы, выделяет кандидаты ударов и создаёт размеченный ролик, статистику и интерактивный таймлайн.

Качество распознавания на произвольных трансляциях пока не подтверждено экспертной разметкой. Оценки модели не заменяют судейство; интенсивность — относительный индекс, не физическая сила. При недостаточном покрытии личностей прогноз результата скрывается.

Текущая реализация, измеренные результаты и ограничения: [cooperative-v3](docs/cooperative-v3-implementation.md).

## Windows-приложение

Нативная оболочка без браузерной адресной строки, подготовленный демо-разбор при запуске и сборка установщика описаны в [инструкции Windows](packaging/windows/README.md). Текущие ограничения — в [статусе сборки](packaging/windows/STATUS.md).

Эта ветка содержит исходники и сценарии сборки, а не проверенный EXE. Для создания `.exe` нужен Windows x64. Частные видео, модели и шрифты не публикуются в репозитории; сборщик принимает их отдельно по проверяемому манифесту.

## Быстрый запуск на macOS

Требования: macOS, Python 3.11+ и FFmpeg с `libx264`. Если FFmpeg отсутствует:

```bash
brew install ffmpeg
```

1. Дважды нажмите `start.command` или выполните `./start.command` в Terminal.
2. Откройте `http://127.0.0.1:7860`.
3. Загрузите MP4, MOV или MKV и задайте начало активного боя, раунды и имена.
4. Проверьте три предложенных кадра. Выберите красного A и синего B кликом по настоящим рамкам детектора. По умолчанию поиск идёт без ограничения; четыре точки нужны только в режиме «Рабочая область». При ошибке замените кадр или исправьте выбор.
5. Нажмите «Подтвердить три кадра», затем «Запустить анализ». Первые 10 секунд проверяются диагностически и не блокируют обработку при перекрытии или отсутствии бойца. Неподтверждённый боец временно не участвует в подсчёте ударов; после уверенного восстановления анализ продолжается. Неверная разметка (например, один человек выбран за обоих) по-прежнему требует исправления. Режим «Без ограничения» отключает только границы области, а не проверку личности.

Первый запуск может установить зависимости и скачать веса YOLOX/RTMPose. После подготовки окружения обработка выполняется локально; файлы не загружаются в облачный ML-сервис. Приложение не скачивает ролики по YouTube-ссылкам. Используйте видео, на анализ и показ которого у вас есть разрешение.

Для уже подготовленного окружения, в том числе текущего UI на порту `7862`:

```bash
BOXING_VISION_PORT=7862 .venv/bin/python app.py
```

Адрес — `http://127.0.0.1:7862`. Не запускайте вторую копию на занятом порту. Изменение Python/CSS/JS требует перезапуска приложения и обновления страницы; уже сохранённый MP4 обновляется только после пересборки.

## Проверка и пересборка

- Во вкладке «Проверка личностей и сцен» исправьте спорные траектории/сцены и нажмите «Сохранить и пересчитать». Используется кэш первого прохода: детектор, pose-модель и классификатор повторно не запускаются.
- Выберите событие на таймлайне, чтобы посмотреть его контекст и подтвердить либо отклонить кандидат. Непроверенные атрибуты остаются оценками модели.
- После изменения проверки экспорт помечается устаревшим. Во вкладке «Экспорт» нажмите «Пересобрать MP4»: это только рендер сохранённых наблюдений/событий, не новый ML-анализ.
- Обязательные проверки личностей/сцен блокируют финальный экспорт. Недостаточное покрытие подтверждёнными личностями отдельно скрывает прогноз победителя. Отсутствие обязательных элементов не означает, что все удары проверены экспертом.
- После прерванного пересчёта со статусом `pending` экспорт заблокирован до повторного успешного пересчёта.

## Результаты

Каждый запуск создаёт каталог `runs/<job-id>/`:

- `annotated.mp4` — ролик с боксами, позами, событиями и HUD;
- `events.json` — таймкоды и атрибуты событий;
- `summary.json` — статистика, показатели доступности результата и условный прогноз, если его разрешает quality gate;
- `clips/` — короткие эпизоды вокруг ударов;
- `analysis.log` — технический журнал обработки.

Также сохраняются `scenes.json`, `tracklets.jsonl`, `identity_profile.json`, `review.json`, `tracking_diagnostics.jsonl`, `model_manifest.json`, `body_map_manifest.json` и hover-превью. В `.render_cache/` находятся нормализованное видео, detector/pose-кэш и конфигурация; не удаляйте этот каталог, если планируете проверку или пересборку без повторного анализа.

## Разработка

```bash
.venv/bin/python -m pytest
.venv/bin/python app.py
```

Базовый стек: RTMLib/YOLOX/RTMPose, Roboflow BoT-SORT, PySceneDetect, ONNX Runtime, FFmpeg и Gradio 5.50 с JS-workspace. Ultralytics не используется.

Готовый ACM40960 LSTM применяется только для уточнения техники уже выделенного кандидата. При отсутствии локального bundle режим `punch_model="auto"` сохраняет геометрический baseline. Этот классификатор не распознаёт фон, руку или попадание; его softmax не является откалиброванной вероятностью. Утилита `tools/prepare_punch_model.py` экспортирует его в ONNX в отдельном окружении — Torch не нужен приложению. RF-DETR Nano пока только сравнительный benchmark, не основной детектор.

Источники и контрольные суммы открытых моделей перечислены в [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) и manifests каждого запуска. Приложение проверяет SHA-256 lightweight-checkpoint. Лицензия кода библиотеки не подменяет проверку происхождения весов и обучающих данных; коммерческое одобрение RTMLib-весов и ACM bundle пока не подтверждено.

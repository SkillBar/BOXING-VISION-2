# Cooperative v3: фактическая реализация и проверка

Снимок рабочего дерева и артефактов на 2026-09-04. Это отчёт о реализованном локальном прототипе, а не подтверждение production-качества ML или воспроизведения чужих исследовательских метрик. Незакоммиченные изменения не сбрасывались.

## Что реально включено

| Этап | Реализация | Ограничение |
| --- | --- | --- |
| Подготовка видео | FFmpeg, H.264/AAC, нормализация и сохранённая рабочая копия | Проверен короткий файл; часовая обработка не прошла нагрузочный gate |
| Калибровка | Девять пробных кадров в первых 15 s выбранного участка, три предложения по качеству; ручное подтверждение настоящих detector bbox и ROI | Цвет экипировки только предлагает A/B; это не автоматическое распознавание личности |
| Сцены | PySceneDetect 0.7.1 AdaptiveDetector; сначала ограниченный prefix, полный scan после preflight | Расписание раундов и ручные overrides; нет обученного универсального классификатора «бой/студия/угол» |
| Детектор / позы | RTMLib 0.0.16, YOLOX Tiny HumanArt и RTMPose-S, CPU ONNX Runtime | Детектор распознаёт людей, не роли boxer/referee. На первом проходе позы считаются для найденных людей, не только для keyframes |
| Motion tracking | Roboflow Trackers 2.6.0 BoT-SORT с компенсацией движения камеры и настоящими detector scores | Локальный ID принадлежит одному shot и не является глобальной личностью |
| A/B/OTHER/UNKNOWN | Core/negative galleries, pose-local признаки экипировки, ограниченный offline Viterbi-декодер, unmatched-состояния, повторное подтверждение | Не универсальный learned ReID; новый ракурс и перекрытия могут давать UNKNOWN |
| Кандидаты ударов | `HysteresisPunchProposer`: начало движения, вынос руки, пик, возврат; separate-hand suppression | Это конечный автомат и геометрический baseline, не обученная Pose-TCN |
| Уточнение техники | Готовый ACM40960 LSTM, 25 кадров × 30 fps × 8 COCO joints, ONNX | Четыре класса, без background/hand/outcome; обучение на наших боях не выполнено |
| Повторы | Последовательность визуальных совпадений ≥2 s с согласованным временным смещением, ограниченная shot | Не полноценное понимание broadcast replay; один похожий кадр не достаточен |
| UI и результат | Gradio 5.50 + локальный JS/Canvas workspace, A/B-панели, timeline, inspector, проверка, render-only экспорт | Визуальная полировка и ML-валидация — отдельные gates |

RTMLib-веса проверяются по SHA256. Приложение не импортирует Ultralytics или Torch; Torch/rfdetr используются только в отдельном `models/.export-env` для подготовки сравнительных моделей. На проверенном runtime установлены ONNX Runtime 1.28.0, `supervision==0.26.1`, `trackers==2.6.0`, `scenedetect==0.7.1`.

`supervision==0.26.1` удовлетворяет требованию trackers `>=0.26.1` и не добавляет PyAV рядом с OpenCV/FFmpeg. Это устраняет причину известного macOS-конфликта двух мультимедийных библиотек; dylib вручную не удалялись. [Зависимости supervision 0.26.1](https://raw.githubusercontent.com/roboflow/supervision/0.26.1/pyproject.toml).

## Preflight и два прохода

1. Пользователь подтверждает A/B на трёх кадрах и область ринга. Приложение повторно извлекает enrollment-признаки из нормализованных пикселей. Один detection не может быть обоими бойцами; прочие люди формируют negative-gallery.
2. Выполняется ограниченный scene scan первых ~10 s с lookahead, затем детекция/позы/локальные треки этого prefix. Preflight проверяет долю активных кадров с подтверждённой парой; стартовый порог — 70%. Это внутренний quality gate, не измерение precision на GT.
3. При провале публикуется `preflight.json`, полный ML-проход не продолжается. При успехе выполняется полный scene scan, а обработка кадров продолжается без повторной детекции prefix.
4. Первый проход сохраняет все detector-tracklet свидетельства. Внутри shot offline-декодер назначает A/B либо оставляет unmatched/OTHER/UNKNOWN. Core-gallery не заменяется внешностью случайно захваченного человека. Новый shot сбрасывает motion-состояние; автоматического надёжного переноса ROI на произвольный новый ракурс пока нет.
5. Кандидаты допускаются только при подтверждённых A+B и `ACTIVE_FIGHT`. Temporal-последовательности разрываются при cut/lost/break/replay. Соседние импульсы одной руки объединяются; разные руки не склеиваются только из-за близкого времени.
6. Вокруг существующего кандидата читаются плотные 30 fps окна. Выполняется только pose inference в проверенных интерполированных bbox, без нового детектора. Между соседними detector frames должны совпадать shot, source ID и роль; пропавший кадр, UNKNOWN, склейка, break или слабый margin разрывают окно.
7. ACM LSTM получает точное shoulder-centred/shoulder-width preprocessing исходного проекта. Sparse/resampled вход — только диагностический. Если геометрия и сильный ответ модели противоречат друг другу, техника становится `unknown` и требует проверки. Модель не устанавливает попадание и не повышает composite confidence автоматически.
8. Результаты рендерятся из сохранённых observations/events. Один neural label не становится подтверждением реального удара.

Калибровка confidence на независимом датасете не выполнялась. `identity_confidence`, геометрический confidence и softmax имеют разный смысл; их нельзя трактовать как одинаково измеренные вероятности правильного ответа.

## Проверка без повторного ML

`cache_review.redecode_from_cache()` валидирует идентификаторы траекторий, сцены и конфликтующие назначения до изменения файлов. Затем переиспользует сохранённые detections/poses; нейромодели не конструируются и не вызываются.

- Dense-кэш перепривязывается по точной временной принадлежности к соседним detector frames, а не по последнему состоянию track ID.
- Ручные confirmed/rejected и уже полученная model-evidence переносятся one-to-one: тот же attacker, defender, hand и round, peak не дальше 100 ms, неизменные личности/траектории обоих бойцов на всём контексте события. Новые или неоднозначные кандидаты остаются baseline.
- Решения, которые нельзя безопасно применить к новому набору, сохраняются в `review.json:event_review_history`; они не превращают неверную личность в подтверждённую.
- Запись подготовлена в staging-каталоге. Перед заменой файлов summary помечается `review_recompute_state="pending"`, результат скрывается, экспорт устаревает. При штатной ошибке выполняется rollback; final summary со статусом `complete` записывается последним. При аварийном завершении pending блокирует export до повторной успешной проверки.
- `rebuild_from_cache()` перерисовывает MP4, события/HUD и превью из кэша. Детектор, позы и LSTM не запускаются.

`required_review_count` относится к обязательным спорным личностям/сценам. Ноль здесь не означает, что эксперт подтвердил все кандидаты ударов. Прогноз победителя отдельно скрывается при внутреннем покрытии <90%, подозрении на конфликт identity или незакрытых обязательных проверках.

## Benchmarks готовых моделей

| Модель | Условия | Median / p95 |
| --- | --- | --- |
| YOLOX Tiny | 24 кадра 0–12 s, CPU 4 threads, preprocess+inference+postprocess | 13.55 / 21.54 ms |

RF-DETR в среднем нашёл 4.17 человека против 3.50 у YOLOX. Без GT больше detections не означает лучшее качество; пороги не откалиброваны между моделями. В отчёте `winner=null`, модель не переключалась на RF-DETR. LSTM timing не включает стоимость получения плотных pose windows и не является скоростью всей системы.

## Лицензии и готовность

- [RTMLib](https://github.com/Tau-J/rtmlib), YOLOX/RTMPose: лицензия кода не доказывает происхождение конкретных весов и всех датасетов. В runtime manifests их weight provenance и `commercial_approval` остаются непроверенными.
- [ACM40960/Boxing](https://github.com/ACM40960/Boxing): MIT-код и готовый checkpoint, pinned revision/hash, safe `weights_only=True` загрузка в exporter. Отдельное полное разрешение на веса/данные не опубликовано; `commercial_approval=false`. Чужое Ultralytics-приложение не подключается.
- [RF-DETR Nano](https://rfdetr.roboflow.com/learn/pretrained/): выбран Apache-2.0 COCO-вариант, не Plus. Bundle используется для benchmark; окончательная проверка прав проекта и исходных видео не подменяется лицензией модели.
- Olympic Boxing Dataset автоматически не используется. Ни обучение нового Pose-TCN/RGB-refiner, ни fine-tuning boxer/referee detector на нём или другом наборе не выполнялись.
- Реальные demo-портреты служат только интерфейсными примерами и не участвуют в идентификации видео. Атрибуция фотографий, моделей и ассетов — в [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md).

Что **ещё не пройдено**: экспертные identity precision/IDSW/referee assignments, punch F1 ±300 ms, hand/technique/target/outcome accuracy, ECE, 6–8 независимых боёв с grouped split, произвольные ракурсы/перекрытия, пятиминутный runtime/RSS gate, 20–30-minute thermal test и полный visual/accessibility/browser regression. Нельзя заявлять 99% identity precision, F1≥0.75, ноль реальных захватов рефери или production ML readiness по данному sample.

Готовая основа для дальнейшей проверки: `tools/golden_eval.py`, схемы ручной разметки, one-to-one event matching, учёт abstention как FN и duplicate как FP, отдельная проверка hand без тавтологии, group-by-fight/athlete и явный статус прав данных. Разметка не генерируется из собственных предсказаний. Следующий quality gate требует видео с разрешением и независимой проверки тренером.

## Дополнение: единый confidence gate и раздельные видео

Добавлено после исторического snapshot выше. Проверенный новый rebuild того же `cf51a53c`: `2026-09-04T20:24:37.570722+00:00`. Исторические значения не перезаписываются.

Общий `is_confirmed_identity()` теперь используется и в preflight, и в итоговом coverage. Повторная проверка **сохранённых** observations дала 119 подтверждённых пар на 150 кадрах первых 10 s: **79.33%**, а не прежние 120/150 = 80%. Старый `.render_cache/preflight.json` всё ещё содержит исторические 80%; этот файл не выдаётся за результат нового ML-прогона. Новое значение также выше preflight-порога 70%.

Полное покрытие не изменилось: **132/180 = 73.33%**. Это по-прежнему внутренний показатель доступности пары, не измеренная по разметке точность. Пересчёт правила подтверждения не запускал детектор, позы или LSTM; он не означает ни переобучение, ни ухудшение модели. Победитель остаётся скрытым.

Экран просмотра и скачиваемый результат теперь используют разные ролики:

- `workspace-preview.mp4` — tracking-only: рамки/скелет без дублирующих HUD-карточек внутри видео; подробная информация остаётся в панелях workspace.
- `annotated.mp4` — отдельный экспорт с выбранным HUD, включая карточки бойцов в compact-режиме.
- Оба потока рендерятся из одного декодирования исходного видео и одних сохранённых наблюдений. Повторного ML для второго ролика нет.

Новый render-only rebuild занял **15.563 s** по summary (**15.564 s** в log), включая подготовку двух роликов. В metadata появились `workspace_preview="workspace-preview.mp4"` и `workspace_preview_mode="tracking_only"`. `ffprobe` подтверждает для workspace-preview H.264 1280×720, 30 fps, 12.000 s и AAC 11.980998 s. Исходное время ML-прохода 63.781 s не изменилось; это всё ещё не длительный performance/thermal gate.

В интерфейсе удалена отдельная видимая подпись о демонстрационном портрете. Сведения о происхождении/условиях фотографии сохранены в атрибуции и доступных `alt`/`title`; фотографии не становятся свидетельством личности спортсменов на загруженном видео.

Основная типографика подключает локальные SF Pro Text Regular/Medium/Semibold/Bold через `local()` и системный fallback. Локальный Druk остаётся display-шрифтом для крупных числовых показателей и A/B. Файлы коммерческих шрифтов не копируются в приложение; на другом компьютере результат зависит от установленных шрифтов. Эти UI-изменения не объявляют пройденными ранее перечисленные visual/accessibility или ML accuracy gates.

### Последующие исправления типографики

Обычные строки ударов и кнопки переведены в Regular, активные переключатели — Medium, выбранный удар — Semibold. Исход расположен под названием, а не под таймкодом; уверенность остаётся в inspector и доступном описании. Inspector показывает миниатюру, заголовок, результат, три поля контекста и вертикальную навигацию. Три действия review сохранены в меню «Проверить».

По последнему запросу возвращены четыре прямоугольные плитки 2×2: интенсивность, блокировано, промахи, не определено. Значения — Druk 28/30, основные попадания/попытки и точность — 32/34. Для устойчивой загрузки установленный Druk теперь доступен браузеру по локальному HTTP через allowlist двух конкретных файлов. Каталог Fonts целиком не открывается, шрифты не копируются в репозиторий или ZIP. Endpoint Medium проверен: HTTP 200, font/ttf; браузер использует семейство BV Druk Runtime. SF Pro остаётся текстовым шрифтом.

Последнюю визуальную проверку кликов временно перекрыл внешний слой комментариев Codex (не часть приложения). Его не удаляли программно; для продолжения проверки пользователь должен выйти из режима комментирования. Это не даёт оснований объявлять весь responsive/fullscreen gate пройденным.
